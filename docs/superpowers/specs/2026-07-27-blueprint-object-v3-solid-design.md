## 0. 问题诊断（David 反馈 → 根因）

| 反馈 | 根因 |
|---|---|
| 字体太小看不清 | SVG 标注 `fontSize: 8` + 最暗档 `txt-quaternary`；3D 面被栅格化成纹理再透视变换，右侧面模块码再吃 `rotateY(90°)` 前缩，实际可读尺寸 5–6px |
| 分辨率/细节不够 | 物件仅 280×344 CSS px（桌面右列有 ~430px 余量）；CSS 3D 的分辨率上限 = 元素布局尺寸，1px hairline + 0.22–0.3 alpha 蚀刻栅格化后糊成灰雾 |
| 透明感、轻飘 | 面板实底 `#111620` 与页底 `#080B10` 亮度只差 6%，且无受光/压暗的明度层次——人眼把「与背景难分离的暗面」读作透明空壳 |

四项方向决策（2026-07-27 David 确认）：**放大到 360px 原生重标 ／ 哑光实体机身
／ 标注全档 11px 提亮 ／ 蚀刻细节加密**。

实现路径定案：**360 原生重标**（方案 C）。否决 CSS `transform: scale()`（3D 面按
布局尺寸栅格化，放大位图 = 复刻病因）；否决「280 逻辑坐标 × 容器系数」（蚀刻本次
全部重画，换算层白白增加心智负担且字号/栅格全是非整数）。

## 1. 几何 — 360×440×150 竖塔（桌面）

- 总体：280×344×120 → **360×440×150**；缝隙 6px → **8px**；core 前脸内凹 8px → **10px**
  （frontZ 75、coreZ 65）；缝光条 z 54 → **66**（埋于前面板后 9px，16° 俯角下漏出可感知光带）。
- `DEPTH` 从共享常量改为 **per-variant**（桌面 150 / 移动 120），`VariantConfig` 新增
  `depth` / `coreFrontZ` / `seamZ` / `labelSize` 四字段。

## 2. 材质 — 哑光实体（透明感的根治）

原则：**面与面的明度差 + 棱线厚度暗示才是「实心」的来源**，不是 alpha。光源与
墙 v8 掠射光同向（左上前方）。

```
--front: linear-gradient(160deg, accent .10, accent .02) + var(--bg-elevated)
         + inset 顶棱受光 rgba(255,255,255,.06) 1px + inset 底缘压暗 rgba(0,0,0,.35) 1px
--top:   linear-gradient(180deg, rgba(255,255,255,.05), transparent 60%)
         + linear-gradient(180deg, accent .20, accent .06) + var(--bg-elevated)   ← 受光面最亮
--right: linear-gradient(200deg, rgba(0,0,0,.30), rgba(0,0,0,.55)) + var(--bg-elevated) ← 背光面最暗
--core:  radial(环心 accent .16) + front 同栈
```

inset 白棱线是把按钮系统的「中性白受光棱线」明度轴豁免**扩展到物件面**——
CLAUDE.md §4 BlueprintObject 豁免条目同步补写（明度轴不是第二色相，逻辑同源）。

## 4. 蚀刻加密（桌面逐模块清单）

编号纪律核查：放弃 REV 假修订号（非真实序列），改用**图形比例尺**呼应 1:1 单元格；
新增蚀刻全部为走线/刻度/孔位/端口等非文本图形，自由文本 mono 标注仍只有
`H 440` 一处（页面级 TORONTO 坐标另计），预算 ≤2 不破。

- **M.01 图签**：分栏线 x216/x288；SYNTHMIND ｜ S.01 ｜ 1:1 三值 11px；
  左栏空区补图形比例尺（主线 M100 33 H188 + 大小刻度交替）。
- **M.02 格栅**：3 条 → 6 条（y16..66，末条短）；对角安装孔 r2.5 ×2。
- **M.03 分线**：主干 x128 承接 M.04 出线 → 双分支入焊盘（44,38)/(176,38) 36×28，
  焊盘中心点 + 主干节点；焊盘之间补 **2×3 端口阵列**（8px 方格，x108/124/140 × y44/56）。
- **M.04 核心**：环 r31 + 罗盘主刻度 4 向加长；**r37 虚线刻度圈**（dasharray 24 段，
  bp-fade 非 draw——`.bp-draw` 的 pathLength 归一化与装饰性 dasharray 互斥）；
  环内十字准星；**取景器四角括弧**（82/164 × 18/100 对称框定核心）；右侧
  **服务分缝** x292 竖 hairline + **状态 pips** 3 格（x304/318/332 y92，首格 NodeDot 点亮）；
  入线 M193 0.5 V59 H166、出线 M123 102 V108 H256 V117.5（跨缝对齐 M.03 主干 x256→局部 128）。
- **M.05 输入**：主文档 (30,14)-(102,70) 标题行 + 3 内容行；**队列第二文档**
  (114,22)-(168,62) 2 行；出线 M102 42 H193 V83.5（跨缝对齐 M.04 入线 x193）；
  右区**双内向箭标**（数据流入暗示，x306..338）。
- **M.06 顶盖左**：角部裁切 ×2 + **刻度尺**（基线 M40 46 H192，大刻度 5 + 小刻度 4 交替）。
- **M.07 顶盖右**：单端口 → **2×2 端口阵列**（14px，x42/64 × y12/34），左上格 NodeDot 点亮。
- **顶面 M.06**（232×150）：十字基准 + r10 基准环 + **四角安装孔** r3 + 前棱刻度 ×3。
- **顶面 M.07**（120×150）：前棱刻度 ×2 + 安装孔 r3 ×2。
- **右侧面**：模块码 11px（tertiary）；M.04 面板缝 y33/85、M.05 y42（x52..135，DEPTH 150 换算）。

跨模块走线在缝口全局对齐：M.05 出 x193 → M.04 入 x193；M.04 出 x256 → M.03 入
（局部 x128）。

## 5. 移动变体（几何 300×168×120 不动，材质/标注/密度提档）

- 受 320px 窄屏约束几何不放大；材质栈/描边提档随共享 CSS class 与 STROKE 常量自动生效。
- 标注 8 → 10px（labelSize=10）。
- 蚀刻小幅加密：核心环补十字准星 + r20 虚线刻度圈；M.03 端口 → 2×2（12px）+
  竖向汇流母线；M.05 格栅 3 → 5 条。
- asm/drift/hover 偏移、缝表、时序全部不动。

## 6. 场景适配

- rootClass：`h-[420px] w-[280px]` → **`h-[540px] w-[360px]`**；floatClass：
  `top-[44px] h-[344px]` → **`top-[56px] h-[440px]`**（顶面投影预留 150·sin16° ≈ 41 + 余量）。
- `.bp-object-backglow` 默认宽 380 → **460**（移动 340 不变）；`.bp-object-shadow`
  240×36 → **300×44**。
- HomeHero 布局不动：1024px 断点下右列 5fr ≈ 386px ≥ 360px；`min-w-0` 护栏已存在。
- `bp-core-pulse` 桌面描边宽 6 → 7（随环径）。

## 7. 不变量继承（全部照旧，实施时不得破坏）

- `.bp-draw` 只用于 `<path>`；圆/矩形一律 A/H/V 路径命令改写。
- WebKit 零平面相交：内墙右面/非顶行顶面不渲染；缝光条只做平行溢出。
- 透视链：scene → spring → root → float → sway → 本体 → 模块三层全程 preserve-3d。
- 三层 transform 解耦（asm/drift/hover 永不同元素）；RM 三件套（globals.css 已有块自动覆盖）。
- 入场编排 Draft→Build→Ship 时序表（T/MT）逐字继承，不改任何 delay。
- 新增的虚线刻度圈用 `bp-fade`（非 draw）——dasharray 与 pathLength 归一化互斥。

## 8. 风险与验证

- **1024–1152px 视口**：物件放大后与文案列间距变紧，实施后该区间实测一轮。
- **3D 文字清晰度**：11px 在栅格化纹理上仍有轻微重采样柔化——验收标准是「正常
  阅读距离可辨识」，不是位图级锐利（渲染管线上限）。
- 验证走真浏览器截图（3100+ 端口纪律；WebKit 截图压扁属工具假象，以 Chrome 为准）。
- 工作区并存 v8 墙未提交改动：本次只外科手术式编辑 bp-object 相关块，不触碰
  `.bp-wall*`；代码与 v8 改动的提交时机由 David 统一决定。
