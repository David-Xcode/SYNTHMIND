## 1. 概念（第一性原理）

**墙 = 一面被 45° 掠射光斜照的实心石墨砌体；指针 = 压在上面的重力井。**

- **墙后没有任何发光体**——角落余晖、全场环境垫光、指针灯全部退役
- 厚度不靠光渗出来，靠**材料自己**读出：受光棱线 / 倒角亮带 / 背光压暗带 /
  凹槽的凸凹线索对调 / 逐砖明度不均
- 深度不靠变亮，靠**变暗**：砖陷得越深越暗（露出砖床槽底）——坑里本来就该暗
- 设计立场：**没有发光体，只有材料和阴影**。科技感彻底退成底色，这是
  Blueprint「静默精密」在背景层的终点形态

### 1.1 与 v6 的语义反转对照

| 通道 | v6 灯箱墙 | v8 石墨墙 |
|---|---|---|
| 砖面 alpha | 0.9 半透 —— 让墙后灯光透 10% | **1.0 不透明** —— 实心石板 |
| 井深处 `opacity` 降 | 露出墙后的**光** → 变亮 | 露出砖床**槽底** → 变暗 |
| 缝隙 | 真空隙，光从缝里透出 | 真凹槽，缝里是**阴影** |
| 光源方向 | 墙后（右上角余晖 + 指针灯） | **左上 45° 掠射**（唯一，全站统一） |
| 蓝味来源 | 光是蓝的 | 只剩受光棱线里 α0.028 的一丝（单色相签名） |

## 3. 材质 token（`--wall-*` 簇 · 新增）

墙自立门户：`--mat-*` 保持不动（BlueprintObject 仍是蓝图蓝发光模块——那是
**内容层**的光，合法且不受本次影响）。玻璃 `--glass-*` / 砖 `--wall-*` /
物件 `--mat-*` 三簇分离，共享明度轴逻辑不共享值。

```css
/* 砖体（石墨石板） */
--wall-face-base:  #111620;                  /* = bg-elevated；--mat-face-base 的不透明形态，零新字面色 */
--wall-face-lit:   rgba(255, 255, 255, 0.055); /* 上棱受光（中性明度轴豁免） */
--wall-face-lit-k: rgba(255, 255, 255, 0.03);  /* 左棱受光（侧受光弱于顶） */
--wall-face-tint:  rgba(74, 159, 229, 0.028);  /* 受光面里一丝蓝 ← 全墙唯一蓝味 */
--wall-face-shade:   rgba(0, 0, 0, 0.42);      /* 下缘背光压暗带 */
--wall-face-shade-k: rgba(0, 0, 0, 0.3);       /* 右缘背光压暗带（侧背光弱于底） */
--wall-face-edge:    rgba(0, 0, 0, 0.3);       /* 下 1px 硬暗棱 */
--wall-face-edge-k:  rgba(0, 0, 0, 0.2);       /* 右 1px 硬暗棱 */

/* 砖床（凹槽） */
--wall-bed-base:   #080B10;                    /* = bg-base，零新字面色 */
--wall-bed-shade:  rgba(0, 0, 0, 0.45);        /* 槽整体压暗 → 有效 rgb(4,6,9)，比 bg-base 更暗 */
--wall-bed-lit:    rgba(255, 255, 255, 0.018); /* 槽内下/右壁反弹光 hairline */
--wall-bed-dark:   rgba(0, 0, 0, 0.35);        /* 砖窝底内阴影峰值 */
--wall-bed-dark-t: rgba(0, 0, 0, 0.4);         /* 横槽上壁：上一块砖的接触投影 */
--wall-bed-dark-k: rgba(0, 0, 0, 0.28);        /* 竖槽左壁：左一块砖的接触投影 */
```

⚠️ 砖窝底内阴影（渐变 `s`）从 offset 0 的**全透明**起、0.06 才到 0.35 峰值：
真砖 div 的抗锯齿上边缘会漏出其下砖床，峰值若压在 y=0 会在每块砖顶缘织出暗线。

**色彩纪律合规**：全部落在既有豁免内——既有 hex 的不透明/rgba 形态
（`#111620` / `#080B10`）+ 中性明度轴（白/黑低 alpha）+ accent 低 alpha。
**零新字面色**。

## 4. 单块砖的光学配方（光自左上 45°）

tile 坐标系沿用 v6 的 96/90 体系（pitch 96 / seam 6 / face 90，即 `seam = pitch/16`）：

| 层 | 几何（90 单位） | 值 |
|---|---|---|
| 实底 | 满铺 | `--wall-face-base` |
| 蓝味 | 垂直渐变 0 → 55% | `--wall-face-tint` → 透明 |
| 下缘背光带 | 垂直渐变 78% → 100% | 透明 → `--wall-face-shade` |
| 右缘背光带 | 水平渐变 82% → 100% | 透明 → `--wall-face-shade-k` |
| 上倒角亮带 | 垂直渐变 0 → 10%（= 9 单位 ≈ 5px @56 档） | `--wall-face-lit` → 透明 |
| 左倒角亮带 | 水平渐变 0 → 10% | `--wall-face-lit-k` → 透明 |
| 上硬棱 | 1 单位横条 | `--wall-face-lit` |
| 左硬棱 | 1 单位竖条 | `--wall-face-lit-k` |
| 右硬棱 | 1 单位竖条 @x=89 | `--wall-face-edge-k` |
| 下硬棱 | 1 单位横条 @y=89 | `--wall-face-edge` |

**倒角亮带是厚度的主要来源**：带越宽、明暗差越大，眼睛读到的板越厚。

## 5. 砖床与凸凹线索对调

`.bp-wall-face` 在 `[data-live]` 下**不再 `visibility: hidden`**，而是丢掉砖层
只留砖床层（`background-image` 少一层）。砖床在两条路径**共用同一张 tile** ——
几何对齐由构造保证，不可能错位。

**砖图也只有一张**（96 viewBox，砖体画在 `translate(6,6)` 的 90×90 区、缝区透明）：
静态路径直接平铺；真砖 div 用 `background-size: var(--wall-brick-w)` +
`background-position: calc(-1 * var(--wall-seam))` 把同一张图对位到
`faceSize = pitch − seam` 的元素盒。各 MQ 档自动成立（56−3.5 / 64−4 / 96−6
同为 16:1）。**禁止再引入第二张砖图**——双份 ~1.4KB 字面值的手工同步
必然漂移（v8 初版曾有 90/96 两张，已合并）。

| 位置 | 砖（凸起） | 槽（凹陷） |
|---|---|---|
| 上 / 左 | **亮**（受光棱 + 倒角） | **暗**（背光内壁 + 上一块砖的接触投影） |
| 下 / 右 | **暗**（背光压暗带） | **亮**（`--wall-bed-lit` 受光内壁） |

这是人眼判定凸凹的经典依据：**明暗方向相反 = 一凸一凹**。砖的接触投影画进床 tile
（静态即可——砖只会陷下，永不抬起），因此**不需要 700 个 `box-shadow`**。

砖床槽底另叠一道自上而下的内阴影渐变（`--wall-bed-dark` → 透明，覆盖上 45%），
表达「光照不到井的深处」——砖 fade 露出时深度感翻倍。

## 6. 逐砖明度微差（质感的真正来源）

真砌的墙不可能每块砖一模一样。3 个变体按**空间哈希** `variantOf(c, r)`
分配（实现与理由见下方 🚨 块）：

| 变体 | 实现 | 相对明度 |
|---|---|---|
| `.bp-brick--a` | tile 上叠 `linear-gradient(rgba(0,0,0,0.035), …)` | **−3.5%** |
| `.bp-brick`（基态 b） | tile 原样 | 0 |
| `.bp-brick--c` | tile 上叠 `linear-gradient(rgba(255,255,255,0.004), …)` | **+4%** |

🚨 **分配函数必须非线性**。任何线性式 `(a·c + b·r) % 3` 的等值集都是直线，
整面墙会织出规则的 45° 对角条纹——**与系数是不是素数完全无关**
（7 ≡ 13 ≡ 1 mod 3，故 `(c·7 + r·13) % 3` 恒等于 `(c + r) % 3`；这是本 spec
初版的错误，已由代码审查捕获）。现行实现 = 大素数乘 + XOR + 位混合：

```ts
const variantOf = (c, r) => {
  let h = (c * 73856093) ^ (r * 19349663);
  h ^= h >>> 13;
  return VARIANTS[(h >>> 0) % 3];   // >>> 0 不可省：^ 产出有符号 int32
};
```

🚨 **`0.004` 不是笔误，不要「修正」它**。覆盖层在深色底上的明度杠杆极度不对称：
结果 = `base × (1−α) + 255 × α`。在 `rgb(17,22,32)` 上——
黑 α0.035 → 乘 0.965 = **−3.5%**；白 α0.022 → R 从 17 抬到 **22.2 = +31%**（砖会发白）。
要做同量级的 +3.5%，白侧只需 **α ≈ 0.004**（≈1/255，alpha 量化的最小可用步）。
三变体均值 ≈ +0.2% ⇒ 接管时**全墙明度无整体台阶**。

- **三变体共享同一张 data-URI**（存进 `--wall-tile-brick` 变量，`background-image`
  多层叠加）——零 tile 重复，零逐帧成本（建砖时定一次 class）
- 变异**只在真砖阵**；静态 tile 用基态 b 单一明度。接管瞬间**单砖**最大差 4%、
  **全墙均值差 ≈0**

### 6.1 接管差异的实测口径（v6「像素等价」→ v8「感知等价」）

240×180 视口下逐像素比对真砖层与静态层（井已归零、砖全部静止原位）：

| 区域 | 像素数 | 平均通道差 | 最大通道差 |
|---|---:|---:|---:|
| 砖体内部 | 39 963（92.5%） | **0.74 / 255** | 8 |
| 砖上/左缘 1px 环带 | 3 237（7.5%） | 11.26 / 255 | 29 |

- 内部差 = 设计意图的逐砖明度变异，均值 0.3%，感知阈下
- 环带差 = **半像素抗锯齿**，不是错位：砖盒落在 3.5px 的分数位上，
  「DOM 元素边缘」与「画在 tile 内部的边缘」栅格化方式不同
  （真砖层更锐：亮棱 40 vs 静态 37 且不摊到相邻行）。错位会表现为
  整体平移，实测 y≥5 起两条路径逐像素一致 ⇒ **对位正确**
- ⚠️ 此差异**v6 即已存在**（同样是分数位 DOM 砖 vs 平铺 tile），v6 的
  「像素等价」本就是近似说法；v8 只是把它测出来并改成诚实口径
- 56 档的 `seam = 3.5px` 是分数位的根源；≥2200px 的 64/4 档是整数位，
  天然无此环带。**若将来要彻底消除，唯一干净解是把基准 pitch 改成 16 的
  倍数**（= 改墙密度，属设计决策，v8 不动）

## 7. 井的物理（深而窄）

| 参数 | v6 | v8 | 理由 |
|---|---:|---:|---|
| `DEPTH` | 16 | **36** | 按压幅度（本次核心诉求） |
| `RADIUS` | 200 | **150** | 收窄 → 坡陡；≈5 块砖直径（v6 为 7） |
| `TILT`（上限） | 15° | **20°** | 陡坡配深井 |
| `FADE` | 0.25 | **0.35** | 露槽底 = 变暗（语义反转） |
| `PULL` | 3 | 3 | 上限 = 缝宽 3.5px，坑心缝闭合不互叠 |
| `SHRINK` | 0.05 | 0.05 | 透视另有 5.7% 缩，合计 ≈10% |
| `STIFFNESS` | 120 | **105** | 石墨重物：沉稳 |
| `DAMPING` | 18 | **20** | ζ 0.822 → **0.976** 近临界，几乎无过冲 |

### 7.1 已验算的几何不变量

- **倾角实际峰值 8.47°**（不是 20°），且**随 pitch 档变**：`tilt = TILT·w·damp`，
  `w = (1−d/R)²·li`、`damp = min(1, d/face)`，在 `d ≈ 50px` 取极值 →
  **8.47° @56 档 / 7.41° @64 / 4.94° @96**（damp 的分母是 faceSize，
  RADIUS 200→150 的收窄放大了这一耦合）。20° 是**上限**，日常不触及
- **砖永不越过墙面**：砖角抬升的力臂是**半对角** 26.25·√2 = **37.12px**
  （不是半宽 26.25——旋转轴 `(uy,−ux,0)` 过砖心，角到轴的距离
  = 26.25·(|ux|+|uy|)，在轴沿对角时取最大）。以 `u = 1−d/R` 记：
  下陷 `= 36u²`，最坏角抬升 `≤ 37.12·sin(20u°·u) ≈ 12.96u²`，
  故 `z_角 ≈ −23u² < 0` 对所有 d 成立。峰值处实测 z = −16.0 + 5.47 = **−10.5px**。
  **没有任何砖会凸到墙面之前**
- **投影足迹永不外扩**（结论成立，但**不是因为「倾斜只会缩小面内足迹」——
  那是假引理**）：绕面内轴旋转的矩阵 `M = I − (1−cosθ)bbᵀ`，方形的轴对齐
  外接尺寸最坏情况会**变大** `(1−cosθ)·0.207`（轴角 112.5° 时）。倾角峰值处
  26.25 → 26.31px。真正的完整链条是
  `26.31 × 0.978（SHRINK）× 0.977（perspective @ z=−13.96）+ 0.49（pull）
  = 25.63px < 26.25px`。**将来上调 DEPTH/TILT 必须验这条链，不能用假引理**
- **倾斜不互叠**：`max(w·damp) = 0.4233` @d=50 → `pull ≤ 1.27px`，
  对向砖合拢 ≤2.54px < 缝宽 3.5px；倾斜只会缩小面内足迹
- **坑心缝张开**：透视 0.943 × SHRINK 0.95 ≈ 0.896 → 缝由 3.5px 张到 ≈6.2px，
  露出更多槽底（更暗）——形变与明度双线索同向

### 7.2 井心颜色核算

砖 `rgb(17,22,32)`，槽底 `#080B10` + 黑 0.45 = `rgb(4,6,9)`；
井心 `opacity 0.65` 合成 → **`rgb(12,16,24)`**。相对砖面明度降约 25%，
配合缝张开与透视缩小，「陷下去」三重线索齐备。

## 8. 层结构（更新）

```
.bp-wall            fixed inset-0, z -1, pointer-events none（属场景，不变）
├─ .bp-wall-face    砖床 + 砖（无 JS/触屏/RM）… z 1
│                   [data-live] 时丢掉砖层，只留砖床
└─ .bp-wall-grid    真砖阵容器 ………………………… z 2（恒压在砖床之上）
```

- SSR 增量从 4 个空 div 降到 **2 个**
- **单层砖纪律修订**：由「任何时刻只有一层砖」改为
  **「一层砖 + 一层砖床，砖床恒在砖后」**。砖床不是砖也不是光，是砖的凹槽；
  v5「tile + DOM 砖 + 逐格底衬 + 假涌光」四层互相遮掩的架构**仍然被禁**——
  判别标准是：砖床不参与遮掩、不冒充光、不随帧变化
- `.bp-wall-grid` 的 `z-index` 由 1 提到 2（原先靠 DOM 序压 tile，两层共存后写死更稳）
- ErrorBoundary 降级路径不变：WallBricks 抛错 → 卸载 → `teardown()` 删 `data-live`
  → 砖层回到 `.bp-wall-face`，墙完整可读

## 9. 连锁修正（光学统一到左上）

1. **`.btn-secondary` 面基色** `--mat-face-base` → `--wall-face-base`。
   按钮语义就是「砌进墙里的一块砖」，砖变石墨按钮必须跟。
   ⚠️ 面下方**不是墙**而是 `.btn-module-frame::before` 铺的 `var(--bg-base)`
   槽腔实底，所以旧值的实际合成是 `0.9×(17,22,32) + 0.1×(8,11,16)`
   = `rgb(16,21,30)`；换不透明后是 `rgb(17,22,32)`，差 **+1/+1/+2**
   ——不是「零变化」，是感知阈下的位移。
   `--mat-face-base` 本身**不删不改**（BlueprintObject 仍消费其交叉锁定语义）。
2. **按钮槽光的理由改写**：`.btn-module-frame` 的槽内常态微光与 hover 涌光
   原由「与砖墙『光在墙后』同一光学语言」背书，而 v8 墙后已无光。
   现行口径 = **按钮是通电的模块**（primary 本就是 accent 渐变通电砖），
   槽光属**内容层**的光，与墙的零光源纪律**正交而非冲突**——墙侧任何
   形式的发光仍然被禁。光本身不动，只改依据。三处同步：
   `globals.css` 的 `::after` 注释、CLAUDE.md §7、CLAUDE.md §6 白名单条目。
3. **按钮槽腔与墙槽的两档差**（记录，不修）：v8 墙侧有了真槽（砖床，
   合成 `rgb(4,6,9)`），而按钮槽腔仍是 `--bg-base` `rgb(8,11,16)`——亮两档。
   统一会波及全站按钮外观，超出墙体换代范围，故 v8 保留差异并在
   `globals.css` / CLAUDE.md §4 显式注明「不得写成同色」。
4. **玻璃卡内反射方向** `linear-gradient(225deg, …)` → **`135deg`**
   （两处：`.card-glass` 基态 + `@supports` 毛玻璃块，两处注释互相标注）。
   225deg 高光朝右上，是为了对着**本次已删除的右上角余晖**——不改就是
   朝着一个不存在的光源反光。
5. `.hero-glow` **不动**（α 仅 0.04，属内容层柔光，与墙无光不冲突）。
6. `--mat-*` / `BlueprintObject` / `.btn-primary` / 弹簧引擎 / 滚动语义
   **全部不动**。

## 10. 明确不做（YAGNI）

mousedown 加深 · 指针速度拉伸 · 真侧面伪元素（1400 元素，性能不值）·
逐砖 `box-shadow` · 任何滚动耦合 · 噪点/颗粒纹理（白名单禁令）。

**墙只做一件事：被按下去。做到无可挑剔即可。**
