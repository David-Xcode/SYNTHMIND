## 1. 几何：单一事实源 `--wall-brick-h`

**硬不变量（取代 v8 的 `seam = pitch/16`）：**

```
Q = 行高（brick pitch Y）  ← 唯一事实源 --wall-brick-h
P = 3Q                     ← brick pitch X
S = Q / 12                 ← 缝宽（横竖同宽，真实砌体的灰缝各向同性）
W = P − S = 35Q/12         ← 砖面宽
H = Q − S = 11Q/12         ← 砖面高
```

砖面长宽比 `W:H = 35:11 = 3.182:1`（真实模数砖 215×65mm 面 = 3.31:1，
含 10mm 灰缝的 pitch 225×75 = 3:1 —— 本方案与真砖同比例）。

### 1.1 pitch 阶梯（只有一个变量随媒体查询变）

| 断点 | `--wall-brick-h` (Q) | P = 3Q | S = Q/12 | 砖面 W×H |
|---|---:|---:|---:|---|
| 基准 | **60px** | 180 | **5** | 175 × 55 |
| ≥2200px | 72px | 216 | **6** | 210 × 66 |
| ≥3600px | 96px | 288 | **8** | 280 × 88 |

🚨 **Q 必须是 12 的倍数**（保 S 为整数）。加新档（如 ≥5000px）写 `120px`
（→ S=10 / P=360），不要写 `112px`。

**全部为整数 ⇒ v8 §6.1 的「半像素抗锯齿环带」从构造上消失**：v8 基准档
`seam = 3.5px` 让每块砖落在分数位，真砖 DOM 边缘与 tile 内部边缘栅格化方式不同，
实测砖缘 1px 环带平均通道差 11.26/255。v8 当时的结论是「唯一干净解是把基准
pitch 改成 16 的倍数（= 改墙密度，属设计决策，v8 不动）」——本次正好是那个设计决策，
顺带把它解掉。新几何下 `left = c·180 + 5 + shift`、`top = r·60 + 5`、
盒 `175×55` 全是整数，**接管前后逐像素同源**（唯一残余差 = 逐砖明度变异，
均值 0.74/255，设计意图，见 v8 §6）。

### 1.2 为什么 P 与 S 不能做成 `calc()` 派生的自定义属性

🚨 **未注册的自定义属性，其计算值是「`var()` 已代入但 `calc()` 未求值」的 token 流。**
若写 `--wall-brick-w: calc(var(--wall-brick-h) * 3)`，
`getComputedStyle(el).getPropertyValue('--wall-brick-w')` 返回字符串
`"calc(60px * 3)"` → `Number.parseFloat` → `NaN` → WallBricks 的
`buildFailed` 闩锁触发 → **桌面重力井静默消失**（不报错、不掉 lint）。
`@property { syntax: '<length>' }` 能让它求值，但那是 Safari 16.4+ / Firefox 128+
的能力，为一个几何常量押上整个增强层的降级面不划算。

**定案**：
- `:root` 只声明 `--wall-brick-h`（三档阶梯只改这一行）
- CSS 需要 P / 2Q 的地方，在**真实属性**里写 `calc()`（真实属性的 calc 正常求值）
- JS 只读 `--wall-brick-h`，自行派生 `P = 3Q`、`S = Q/12`

⇒ `--wall-brick-w` / `--wall-seam` 两个 token **删除**。
这结构性地关掉 `docs/CODE-REVIEW-2026-07-27.md` 第 91 条
（`--wall-seam` 零 CSS 消费方 + `seam = pitch/16` 硬编三处），
`.bp-wall-grid` 里的 `--seam-guard: var(--wall-seam)` 防死码护栏一并删除
（`--wall-brick-h` 有真实 CSS 消费方，不需要护栏）。

## 2. 砌法：running bond（半砖错缝）

```
行 r=0 (偶)   ┤    ███████████ ███████████ ███████████     ← 右移 P/2
行 r=1 (奇)   ┤███████████ ███████████ ███████████ ██      ← 不移
行 r=2 (偶)   ┤    ███████████ ███████████ ███████████
行 r=3 (奇)   ┤███████████ ███████████ ███████████ ██
```

**DOM 排布（WallBricks）：**

```ts
const shift = r % 2 === 0 ? P / 2 : 0;      // 偶行右移半砖
const cStart = shift > 0 ? -1 : 0;          // 偶行左端补一块（被 contain:paint 裁掉一半）
for (let c = cStart; c < cols; c++) {
  left = c * P + S + shift;
  top  = r * Q + S;
}
```

偶行多一块砖（左端补齐），总数 = `rows·cols + ceil(rows/2)`。

**为什么偶行移而不是奇行移**：静态 tile 把砖画在 `P × 2Q` 画布的**下半格**
（§3.1 的对位恒等式要求），下半格 ≡ 奇行，故奇行是「不移」的那一行。
两条路径的相位必须一致，这是唯一约束，方向本身无所谓。

**错缝的一个物理红利**：重力井的权重在**砖心**采样，砖越长采样越粗，
指针沿一行横滑时单砖沉降会「呼吸」。running bond 下相邻两行砖心相差半砖，
两行的呼吸相位相反、互相抵消 —— 错缝本身就是这个量化伪影的减震器。

⚠️ **这个伪影与砖尺寸档（A/B/C）无关**：`RADIUS` 与砖长同为 Q 的倍数，
`W/R = (35/12)/3.5 = 0.833` **恒定**，选小一档的砖一点也不会缓解（详见 §9 风险 1）。

## 3. 静态 tile：一张砖图表达错缝

### 3.1 构造（不破「全站唯一一张砖图」纪律）

v8 §5 明令**禁止引入第二张砖图**（双份 ~1.4KB 字面值必然漂移）。
running bond 的重复单元是两行 —— 但**不需要**在 tile 里画三块砖：

> **把唯一那块砖画在 `P × 2Q` 画布的「右下格」，上半格全透明。
> 静态层用同一张图叠两遍，第二遍偏移 `(P/2, Q)`。**

- 层 A（`background-position: 0 0`）→ 铺出所有**奇行**（不移）
- 层 B（`background-position: 1.5Q, Q`）→ 铺出所有**偶行**（右移 P/2）
- 两层的砖在 y 上互不重叠（A 在 `[Q+S, 2Q]`，B 偏移后落在 `[S, Q]`）⇒ 零遮掩

**砖必须在右下格，不能在左上格** —— 这是 `.bp-brick` 对位恒等式的要求，见 §3.2。

### 3.2 对位恒等式（v8 的 `100% 100%` 原样成立）

`.bp-brick` 元素盒 = `W × H`，要把 `P × 2Q` 画布里那块砖精确铺满它：

```
background-size:     calc(100% * 36/35)  calc(100% * 24/11)
background-position: 100% 100%
background-repeat:   no-repeat
```

推导（以 S 为单位：P=36S, Q=12S, W=35S, H=11S）：

- **x**：图宽 = `W·P/W = P`；`容器W − 图W = W − P = −S`；`position-x: 100%` 恰给 `−S` ⇒ 图 x=S 落到元素 x=0 ✓
- **y**：图高 = `H·2Q/H = 2Q`；`容器H − 图H = H − 2Q = −(Q+S)`；`position-y: 100%` 恰给 `−(Q+S)` ⇒ 图 y=Q+S 落到元素 y=0 ✓

**砖若画在上半格**，需要的 y 偏移是 `−S`，对应百分比 `S/(Q+S)` = 7.6923%
—— 一个不透明的魔数。**右下格是唯一让两轴都落在 `100%` 的位置。**

代入基准档验算：元素 175×55 → `background-size` = `(175·36/35, 55·24/11)`
= **(180, 120) px**；tile 288×192 单位渲染成 180×120 px ⇒ 1 单位 = 0.625px（xy 同尺度 ✓）；
砖面在图中 x∈[5,180]、y∈[65,120] px；`position 100% 100%` 给偏移 `(175−180, 55−120)`
= `(−5, −65)` ⇒ 砖面精确落在 `(0,0)–(175,55)` ✓

### 3.3 tile 坐标系

两张 tile 同为 **viewBox `0 0 288 192`**（= 以 S=8 为单位的 `36S × 24S`），
1 tile 单位 = `Q/96` px（基准档 0.625px，v8 为 0.583px）。

| 元素 | tile 坐标 |
|---|---|
| 画布 | 288 × 192 |
| 奇行砖面（层 A 画的那块） | `(8, 104)` 起 280 × 88 |
| 偶行砖面（层 B 铺出，仅砖床 tile 需画） | `(152, 8)` 起 136×88 + `(0, 8)` 起 144×88（回绕两段） |
| 横缝（bed joint） | y∈[0,8] 与 y∈[96,104]，满宽 |
| 竖缝（head joint） | 偶行 x∈[144,152] @ y∈[0,96]；奇行 x∈[0,8] @ y∈[96,192] |

### 3.5 砖床 tile（`--wall-tile-bed`）

凸凹线索对调（v8 §5）不变：砖上/左亮、下/右暗；槽上/左暗（接触投影）、下/右亮（反弹光 hairline）。
错缝下**横缝仍然通长**（真实砌体的 bed joint 连续），**竖缝逐行错位**。

绘制顺序：底 → 砖窝内阴影 → 竖缝（+其 hairline）→ 横缝（+其 hairline）。
横缝后画 ⇒ 交叉处横缝胜出，与真实砌体「灰缝通长、竖缝顶进去」一致。

## 4. 倒角等物理宽（本次唯一的材质改动）

v8 把四边处理写成「各自占**该轴**的 10% / 18% / 22%」。砖是正方形时这没问题
——上下左右四带同宽（v8 基准档倒角 = 0.10 × 面高 52.5 = **5.25px**，左倒角同值）。
**一旦砖变成 3.18:1，同一套百分比会让左倒角带膨胀到 17.5px、右背光带膨胀到 31.5px**
—— 物理上错（真砖的棱角倒角是固定物理宽度，不随砖长变化），而左倒角带恰恰是
正文对比度最薄弱的那类受光面（17.5px ≈ 2–3 个字符宽）。

**定案**：四边棱线处理统一为**同一物理宽度**（以砖高为基准）：

| 处理 | 宽度（tile 单位） | 基准档 px | v8 在 3.18:1 下会是 |
|---|---:|---:|---:|
| 上/左倒角亮带 | 8.8（= 0.10·H） | 5.5 | 上 5.5 / **左 17.5** |
| 下/右背光带 | 19.36（= 0.22·H） | 12.1 | 下 12.1 / **右 31.5** |

**alpha 一律不动** ⇒ 所有峰值颜色与 v8 逐位相同（§5 会用到这个结论）。
**受光带面积占砖面比例反而下降**：v8 方砖 10%+10%−1% = **19%**；
v9 长砖 10%+3.14%−0.31% = **12.8%（−33%）**。

## 5. 三条重算（David 点名不许拍脑袋的三件事）

### 5.1 砖不得凸出墙面的不等式

**力臂 = 半对角线**（v8 §7.1 的推导对非方砖同样成立，此处补全一般式）：
旋转轴 `b = (uy, −ux, 0)` 过砖心，砖角 `(±W/2, ±H/2, 0)` 到轴的面内垂距
= `(W/2)|ux| + (H/2)|uy|`，在 `u` 取对角方向时达最大 `√(W²+H²)/2` = **半对角**。

```
halfDiag = √(W² + H²)/2 = (Q/24)·√(35² + 11²) = 1.52866·Q
```

基准档 Q=60 → **91.72px**（v8 方砖为 37.12px，×2.47）。

**保证式**（`u = 1 − d/R`，`w = u²·li`，`damp = min(1, d/H)`）：

```
z_角(u) = −DEPTH·u²·li + halfDiag·sin( TILT·u²·li·damp · π/180 ) < 0
```

小角近似下两项同为 `u²` 的一次式，故等价于**一条尺度无关的不等式**：

```
DEPTH/Q  >  (halfDiag/Q) · TILT · π/180
```

代入保守档（`DEPTH = 0.75Q`，`TILT = 20°`）：

```
0.75  >  1.52866 × 20 × 0.0174533 = 0.53357     ✓  余量系数 0.216
```

**这条式子里没有 Q ⇒ 三个 pitch 档 + MAX_BRICKS 封顶档一次性全部成立。**
（v8 的常量是绝对 px，倾角实际峰值随档漂移 8.47°/7.41°/4.94°；v9 把
`DEPTH / RADIUS / PULL / perspective` 全部写成 Q 的倍数后，各档观感完全一致。）

**数值核对（Q=60，li=1）：**

| 量 | 值 |
|---|---|
| `damp = 1` 的临界 | `d ≥ H = 55px` ⇒ `u ≤ 1 − 55/210 = 0.7381` |
| 倾角实际峰值 | `TILT·0.7381² = 20 × 0.54479 =` **10.90°**（v8 为 8.47°） |
| 峰值处砖心 z | `−45 × 0.54479 =` **−24.52px** |
| 峰值处砖角 z | `−24.52 + 91.72·sin(10.90°) = −24.52 + 17.34 =` **−7.18px** ✓ <0 |
| 线性式 | `z_角 ≈ −13.18·u² px`，对所有 `u>0` 严格小于 0 |
| `u>0.7381` 分支 | 倾角随 damp 线性衰减，`z` 单调更负（u=0.8→−13.2 / 0.9→−26.6 / 1.0→−45） |

**pointerdown 深压（li=1.3）：** 沉降项 `∝ li`（线性），抬升项 `∝ sin(·)`（次线性）
⇒ **li 越大越安全，不等式无需重证**。核对：峰值处 `−31.87 + 91.72·sin(14.17°)
= −31.87 + 22.44 =` **−9.43px**（比 li=1 时更深，✓）。

### 5.1.1 投影足迹永不外扩（v8 §7.1 那条「必须验的链」）

绕面内轴旋转的矩阵 `M = I − (1−cosθ)bbᵀ`，矩形的轴对齐外接尺寸**会变大**
（v8 已警告「倾斜只会缩小面内足迹」是假引理）。逐项算（`k = 1−cosθ`）：

```
Xmax = (W/2)(1 − k·bx²) + (H/2)·k·|bx·by|
Ymax = (W/2)·k·|bx·by| + (H/2)(1 − k·by²)
```

最坏情况 li=1.3、u=0.7381、θ=14.17°（k=0.030409），W/2=87.5、H/2=27.5：

| 轴 | 旋转后/静止 | ×SHRINK(0.9646) | ×perspective(0.9496) | 合计 |
|---|---:|---:|---:|---:|
| X | 1.00073 | | | **0.9163** ✓ |
| Y | 1.03552 | | | **0.9484** ✓ |

两轴都 `< 1` ⇒ 足迹恒在静止盒内，`contain: layout paint style` 的 paint
裁切无可见副作用。

**邻砖不互叠**：`pull = PULL·w·damp`，`max(w·damp) = 0.54479×1.3 = 0.70823`
⇒ `pull_max = 3.6 × 0.70823 = 2.55px`。
- **横向邻砖**：半宽 87.5 因缩放退 `87.5×(1−0.9163) = 7.32px` > pull 2.55 ⇒ 缝**恒张开**
- **纵向邻砖**：半高 27.5 退 `27.5×(1−0.9484) = 1.42px`，净进 `2.55−1.42 = 1.13px`；
  两块对合 = **2.26px < 缝宽 5px** ✓（扫 u∈[0.6,0.9] 逐点核过，最大净进 1.14px @u≈0.74）

**坑心缝张开**（形变与明度双线索同向，v8 语义保留）：
`u→1` 时 `damp→0`（倾角/聚拢归零，只剩最深下陷），
`perspective 10Q/(10Q+0.75Q·li) × SHRINK(1−0.05li)`：
- hover（li=1）：`0.9302 × 0.95 = 0.8837` ⇒ 横缝 5→25.3px、竖缝 5→11.4px
- 深压（li=1.3）：`0.9112 × 0.935 = 0.8520` ⇒ 横缝 5→30.9px、竖缝 5→13.1px

按 pitch 归一的 **hover 档**对比（v8 无深压，同档才可比）：v8 坑心缝占 pitch 的
16.0%、v9 横 14.1% / 竖 19.0% —— 同量级，不是新读感。深压档（横 17.2% / 竖 21.8%）
是本次新增的第二级，本来就该更张。

### 6.2 `damp` 的分母为什么必须是短边

`damp = min(1, d/scale)` 的作用是**把坑底放平**（井心处径向方向不定，
倾角/聚拢必须归零）。scale 取 `W=175` 会让 damp 在 `d<175` 全程 <1，
而 `R=210` ⇒ 井里几乎处处被压制，坡度读不出来。取 `H=55`（= 11Q/12）
在 `d≥55` 即饱和，平底区占半径 26%（v8 为 35%）⇒ 碗更陡，与「更重」同向。

### 6.3 pointerdown 深压（新增，推翻 v8 §10 的一条 YAGNI）

v8 §10 把 mousedown 加深列为「明确不做」。**本次由 David 明确要求推翻这一条**
（原诉求「指针**压下去**的凹陷感要更明显、更有回应」——在此之前「压」只是 hover 隐喻，
鼠标真按下去时墙没有任何反应）。

```
pointerdown（非 touch） → pressed = true,  ti = PRESS (1.3)
pointerup / pointercancel → pressed = false, ti = 1
onLeave（pointerleave / blur / visibilitychange） → ti = 0（pressed 一并清）
onMove → ti = pressed ? PRESS : 1      ← 🚨 不能无条件写 1，否则按住拖动会取消深压
li 钳位上限 1 → PRESS
```

- **零新弹簧、零新逐帧成本**：走已有的 `li` 那一根标量弹簧
- **安全性无需重证**：§5.1 已证 li↑ 只让不等式更宽松；足迹链在 li=1.3 下 0.948<1
- **与 pointer-events 无关**：墙是 `pointer-events: none`，但监听挂在 `window`，
  按在任何元素上都收得到 —— 语义正确（「你按了这面墙」）
- 边界：按住拖选文字时井保持深压，属可接受行为

### 6.4 MAX_BRICKS 重算（**确认，不是顺手删**）

砖变大 ⇒ 砖数降。逐场景实算（`cols=ceil(cw/3Q)`、`rows=ceil(ch/Q)`、偶行 +1 列）：

| 视口 | v9 档 (Q) | v8 砖数（封顶前） | **v9 砖数** |
|---|---|---:|---:|
| 1920×1080 | 60 | 700 | **207** |
| 2560×1440 | 72 | 920 | **250** |
| 3440×1440（v8 认定的现实上限） | 72 | 1242 | **330** |
| 3840×2160 | 96 | 920 | **334** |
| 2160×3840 竖置 4K（v8 立项的病态场景） | 60 | 2691 → 封顶 | **800** |
| 2880×5120 竖置 5K | 72 | 3600 → 封顶 | **1044 → 封顶** |

> ⚠️ `docs/CODE-REVIEW-2026-07-27.md:2047` 把 2560×1440 算成 `46×26 = 1196`
> —— 那是拿 56 档算 2560 宽的视口，而 2560 ≥ 2200 应落 64 档，正确值 920。
> 本表按阶梯逐档重算，不沿用那个数。

**裁决：`MAX_BRICKS` 1400 → 900。**
- 护栏的成本模型是**按节点数**（v8：「砖自己不 layout，但让别人的每次全文档
  layout 贵 3–4 倍」），不是按面积 —— 所以绝对阈值应该跟着「多少个节点算贵」走，
  而不是跟着砖变大一起放大
- 1400 在新几何下**几乎不可达**（竖置 5K 才 1044）⇒ 会退化成事实死码。
  900 让它在竖置 5K 及更极端的高瘦视口真实触发，护栏保持**可被验证**
- 竖置 4K（800）不再触发 ⇒ v8 立项时那个场景在新几何下**天然合规**，
  这是砖变大的直接红利
- 封顶算法同步改为**在 Q 上迭代**：`Q ← ceil(Q·√(count/MAX))` 后**上取到 12 的倍数**
  （保 S 整数），再 `while (count > MAX) Q += 12`；砖数对 Q 单调不增，必然收敛
- 封顶时只需把 `--wall-brick-h` 内联写回 `.bp-wall`（**不是 grid**：静态砖床
  `.bp-wall-face` 是 grid 的兄弟节点，只有挂到共同祖先才继承得到）

**旁证**：v4.1 §2.2 实测的砖数预算是「368 砖满帧 / 600 砖 min 67fps」（当时砖带
box-shadow 投影，比 v8/v9 的纯 tile 砖更贵）。v9 的 207–334 落在那条最严苛的
历史实测线以下。

### 6.5 逐帧代码的两处结构改动

1. **砖心坐标改建时预存**（`Float32Array cx / cy`）。错缝下每行砖数不同，
   `i % cols` / `(i/cols)|0` 的行列反推**失效**；顺带去掉每砖每帧一次取模+除法。
2. **`perspective` 建时算一次**（`10·Q`），不在逐帧字符串里重算。

其余全部保留：3 标量弹簧、圈外双零跳过、弹簧收敛即停帧、`buildFailed` 闩锁、
resize 短路、`listenMql` 单向 RM 拆场、ErrorBoundary 降级、只写 transform/opacity。

## 9. 风险与验证

| # | 风险 | 处置 |
|---|---|---|
| 1 | 长砖使重力井的砖心采样变粗，指针横滑时单砖沉降「呼吸」 | **本次最大的未知数，真机首要观察项。** 量化：`W/R = 0.833`（v8 方砖为 0.35）⇒ 指针横穿一块砖时，该砖的 `w` 在 **0.34–1.0** 间摆动（v8 为 0.68–1.0），沉降 15.3–45px。缓解 = running bond 的行间反相（§2）。**不能靠选小一档的砖解决**——R 与砖长同为 Q 的倍数，比值恒定。若真机判定过强，唯一杠杆是**抬 `RADIUS`**：3.5Q → 4.5Q 使 `W/R` 降到 0.65（倾角峰值升到 12.68°，`z_角 = −8.40px` 仍 <0，§5.1 的不等式与 R 无关，安全性不受影响），代价是井直径占视口更大 |
| 2 | 逐砖明度变异（±3.5%）在 3.4 倍面积的砖上更显眼，可能读作「脏」 | 待真机判定。若过强，把黑侧 α 0.035 降到 0.025、白侧 0.004 → 0.003（白侧 alpha 的 8bit 落点是 1/255，**不能四舍五入到 2 位小数**，v8 §6 已警告） |
| 3 | 三层 background（砖×2 + 床）比 v8 的两层多一次合成 | 静态层只画一次、不随帧变；`[data-live]` 后降回一层。可忽略，但真机确认无首屏绘制回归 |
| 4 | 深压在按住拖选文字时井保持深陷 | 定案为可接受行为（§6.3）。若真机觉得干扰，退路 = `pointerdown` 后 400ms 自动回落 |
| 5 | `MAX_BRICKS` 900 在竖置 5K 触发后 Q 被放大，砖更大 | 预期行为（超大屏砖更大合理）。验证封顶迭代收敛且 Q 仍是 12 的倍数 |
| 6 | 错缝下偶行左端补砖被 `contain: paint` 裁一半 | 构造预期（v8 已有右端溢出裁切先例）。验证左边缘无露底 |

**验证矩阵**（全部在 **3100+ 高位端口**跑，不碰 3000）：

1. `npm run build` + `npm run lint` 双绿
2. 桌面 hover 真机：井的塌陷/回弹 GIF；**指针沿一行横滑**观察呼吸幅度（风险 1）
3. **pointerdown 深压**：按下/松开的两级深度差可辨、松开无残留
